# 3D 空间布局

主导航的 `3D 家庭` 是独立的空间优先视图，支持单层户型：用户上传 PNG、JPEG 或 WebP 平面图，先校准一条已知长度，再由控制台在浏览器本地分析 CAD 实心黑墙和双边白芯墙。分析只生成墙图中心线、共享节点和独立墙厚，不从图片生成门窗或猜测房间。用户可选择、拖动、画墙、在点击位置加节点、合并和删除墙边；门窗由用户把已拆分的整条墙边转换得到。`room` 或 `area` 可按墙图节点勾画，也可双击完全闭合的墙图面自动创建。之后从当前 Xiaomi 家庭的真实设备清单按房间和设备图标选择稳定 DID，或选择已解析照明控制身份，并使用地面、中部、顶部三个高度预设放置标记。家具、多楼层和语义型 AI 图像识别仍不在首版范围内。

标尺不会改变墙线检测结果。它只建立 `pixelsPerMeter` 换算，把图上的墙长、墙厚、门窗宽度、房间轮廓和设备平面坐标转换为 GLB 中的米制尺寸。编辑器持续显示 `1 米 = N px` 和估算图纸尺寸；设备高度独立以米保存，地面、中部、顶部目前分别为 0.20 m、1.20 m、2.35 m。

自动识别是确定性计算机视觉辅助，不是权威建筑测量。浏览器直接处理用户上传的像素，不调用模型或上传额外副本。检测器先用 Otsu 阈值形成墨线掩码，再沿墙的横截面寻找达到最小厚度的连续实心核心；只有这些核心沿另一轴持续足够长度时才生成中心线。第二遍会配对相距一个标准墙厚的两条细边界线，将中间留白的双线结构加入同一墙网；候选必须接入已经确认的结构墙，避免文字、尺寸线、床、桌子和柜体轮廓仅因“线很长”就成为墙。可能的门窗间隔只用于连接同轴墙段，不产生门窗对象。编辑器提供最小实心墙厚、最短墙长和短断点距离，并可用当前图片反复重建，无需再次上传。实现参考了 MIT 许可的 [FloorPlanner](https://github.com/pjm4github/FloorPlanner) `fp_extract.py` 墙体提取流程以及 [floorplan-editor](https://github.com/armedad/floorplan-editor) 的厚度/长度清理模型；没有复制其源代码。编辑交互参考 Floorplanner、Sweet Home 3D 和 [Blueprint3D](https://github.com/furnishup/blueprint3d)：中心线保持独立可选，交点和端点组成墙图节点，连接节点组成带 miter join 的显示路径，GLB 在节点处生成同样的斜接面，因此外角不会缺块。合并容差内的墙角端点会焊接到同一个存储坐标；T 形端点落到另一面墙中段时，宿主墙会实体拆分，三条边共享同一个节点。橙色共享节点属于所有相连墙边，拖动时会同时移动这些墙边的端点，并默认吸附为水平或垂直边；按住 Option 可暂时自由拖动。画墙工具用左键连续落点、右键结束。选择墙边后可直接在画布工具栏转换为门或窗。双击或“加节点”在指针位置拆分，键盘支持 `V`、`W`、`Delete` 和 `Escape`。闭合面通过半边遍历识别。斜墙、弧墙和不闭合区域仍可能需要手动修正。

## 数据与存储

生产环境使用独立 EdgeOne Makers Blob namespace，默认名为 `mijia-spatial-layout-v1`，可通过 `SPATIAL_LAYOUT_STORE` 修改。对象键只包含 SHA-256 哈希后的 home ID：

```text
homes/<sha256(homeId)>/current.json
homes/<sha256(homeId)>/revisions/<immutable-revision>.json
homes/<sha256(homeId)>/uploads/<uuid>.{png,jpg,webp,glb}
```

`SpatialLayoutV1` 元数据保存标尺、空间多边形、第一类 `walls` 中心线（端点、像素墙厚、高度和置信度）、绑定到 `wallId` 的门窗以及设备/照明稳定身份。源图和浏览器生成的二进制 GLB 分开保存。生成 GLB 时，门洞会切断整高墙体，窗洞会生成窗台和过梁，而不是把门窗模型叠在完整墙体上。客户端先取得限定对象键、内容类型和有效期的上传 URL；服务器在激活 revision 前重新读取资产，验证长度、图片魔数、GLB v2 头、对象所属家庭和严格元数据 schema。只有全部通过后才写 `current.json`。指针写入失败不会激活不完整 revision。

本地开发服务器在 `NODE_ENV=development`（或显式 `AI_ENVIRONMENT=development`）时使用 `.local/spatial-layout/`，或由 `SPATIAL_LAYOUT_DIR` 指定目录；`.local/` 不应提交。生产环境不会回退到本地文件，Blob 不可用时仍然失败关闭。

## 授权与隐私

四个接口都从加密的 `xiaomi_session` Cookie 读取身份，并在每次元数据读取、资产读取、上传票据、保存和删除前重新获取家庭列表。客户端提交的主体、家庭或权限信息不受信任。布局按 Xiaomi 家庭共享，因此当前仍属于同一家庭的成员看到同一 revision；退出家庭后访问立即被拒绝。

源平面图可能暴露住宅结构和设备位置。响应使用 `private, no-store` 或 `no-store`，对象键不包含原始 home ID，错误消息不包含对象键、DID 或会话数据。删除会清理当前家庭前缀下的元数据和资产。预览/演示数据完全虚构，且不会发送物理控制指令。

## 并发和失败语义

- `PUT` 必须携带编辑开始时的 `baseRevision`。当前 revision 已变化时返回 `409 SPATIAL_REVISION_CONFLICT`。
- `DELETE` 可携带预期 revision；过期删除同样返回 409。
- 上传完成不等于布局生效。无引用的失败上传可由后续维护任务回收。
- Blob 是持久对象存储，不被当作分布式锁。revision 是不可变的，强一致读取当前指针用于冲突检测。
- 物理控制只来自服务端验证过的 MIoT 可写能力。写入超时或无法读回确认时显示“结果待确认”，不会自动重试，也不会乐观显示成功。
- WebGL 初始化或 GLB 加载失败时，语义化设备列表仍可使用；高级控制始终可进入既有设备详情。

## API

- `GET /api/xiaomi/spatial-layout?homeId=…`：读取当前元数据。
- `GET /api/xiaomi/spatial-layout?homeId=…&asset=image|model`：读取当前 revision 的授权资产；模型可加 `download=1`。
- `POST /api/xiaomi/spatial-layout/uploads`：创建限定图片或 GLB 的上传票据。
- `PUT /api/xiaomi/spatial-layout/uploads?...`：仅本地开发存储使用。
- `PUT /api/xiaomi/spatial-layout`：验证资产并激活不可变 revision。
- `DELETE /api/xiaomi/spatial-layout?homeId=…&revision=…`：冲突安全删除。

## 部署配置

EdgeOne 部署应提供平台 Blob 绑定；跨项目 API 访问时还需既有的 `PAGES_PROJECT_ID` 和 `PAGES_BLOB_API_TOKEN`。可选变量：

| 变量 | 用途 |
| --- | --- |
| `SPATIAL_LAYOUT_STORE` | Blob namespace，默认 `mijia-spatial-layout-v1` |
| `SPATIAL_LAYOUT_DIR` | 仅本地开发的文件目录 |

上线前验证家庭隔离、共享家庭访问、图片/GLB 校验、409 冲突、失败激活回滚和删除。不要把 mock 测试描述为真实 EdgeOne Blob 或 Xiaomi 验证。
# 3D 交互与状态反馈

设备标记使用按真实设备类别映射的统一 SVG 图标；缩小时只保留小图标，放大、键盘聚焦或选中后显示名称和可用读数。图标不根据名称推断设备能力。设备状态继续用文字和标记色表达，不在地面绘制状态圆环。窗帘优先采用 current-position 实测值，只有目标值时明确标注“目标”，不视为运动完成。所有已放置设备的可读亮度、目标温度和窗帘位置进入页面即读取，并在每次批次结束 10 秒后继续刷新，无需切换选中设备；控制完成触发新一轮回读，迟到的旧结果不能覆盖确认值，读取失败清除对应参数。

编辑器第 4 步可放置双人大床、衣柜、墙板、沙发和桌子。选中后点击图纸移动，调整米制宽/深/高、旋转角度或删除。家具存放在可选 furniture 字段（最多 200 件），与设备身份和物理控制分离；旧布局兼容，保存后的 GLB 包含家具。它们是几何示意模型，不是厂商素材。

放置设备时，每个灯组可选择“整个灯组”或“分别放置成员”。成员仅来自同家庭已返回的 groupMemberIds 和真实设备列表，分别保留自身身份、控制地址、状态和位置；未返回成员时禁用拆分放置。切换列表方式不会删除已有位置，已有组标记可通过“移除”替换为独立成员，保存后各标记按自身身份恢复。

空间中已放置对象的电源状态在进入页面后直接回读，并每 10 秒按物理 DID 合并读取；确认写入更新同一份状态，旧请求不得覆盖新回读。读取失败保持未知。双指触屏拖动平移且捏合缩放；触控板双指滑动平移、捏合缩放，键盘加减键也可缩放。

快捷控制发出时，空间效果立即进入带“同步中”标记的预测动画，但不会把预测状态描述为已确认。窗帘从当前实测位置向目标位置移动，详情同时显示“当前位置”和“目标位置”；IoT 灯在 1.4 秒内渐亮或渐暗。确认回读清除预测标记，下一次属性或电源读取以真实值校正效果；明确失败立即恢复操作前显示。开启减少动态效果时直接切换到目标预览。

普通照明回路的控制地址优先取拓扑公开地址，再取有线端点公开的 powerControl，始终向物理开关 DID 与对应服务发请求。缺少地址不会猜测服务号。

3D 画布支持拖动旋转、右键平移、滚轮/双指缩放，聚焦画布后方向键平移、加减键缩放。设备状态更新保留相机位置；重置视图恢复全屋视角。

设备明确发布可写的 `motor-control` 属性及对应枚举时，快捷菜单显示打开、关闭和暂停按钮，并使用设备规格中声明的原始枚举值；不按设备名称猜测电机能力。写入后仍按现有规则回读确认，无法回读的结果保持待同步状态且不会自动重试。

查看器提供自动、日间和夜间光照模式。自动模式按浏览器时区对应城市的本地日出、日落切换，不请求定位权限；未知时区使用本地时差的近似太阳位置。手动切换只改变当前浏览器中的背景、环境光和方向光，不修改布局、设备状态或物理设备；切换时保留相机、房间聚焦和已选设备。

3D 视图中的星形按钮默认只显示入口，展开后列出当前家庭的手动场景，可在不离开视图的情况下快速执行。菜单复用场景中心的既有执行流程、并发保护和结果反馈，不新增控制端点；禁用场景不可执行，点击外部或按 Escape 会收起菜单。

查看器提供省电、流畅和标准渲染质量，并把选择保存在当前浏览器。触控设备首次使用默认省电模式；省电模式在交互和动画期间以最高 30 FPS、1 倍像素比渲染。流畅模式关闭抗锯齿并在移动时保持 1 倍像素比，但按屏幕原生刷新节奏提交帧，在 iPad Air 4 上可在场景允许时达到约 60 FPS。两种移动优化模式静止后最高恢复到 1.5 倍像素比。标准模式启用抗锯齿并最高使用 2 倍像素比。聚焦房间时，外围结构使用不参与光照和透明混合的轻量线框，并仅在相机移动期间进一步降低渲染比例；移动停止后立即恢复所选模式的静态清晰度。所有模式在场景静止、页面隐藏或画布离开视口后停止提交新帧，重新可见时恢复一次渲染。

空间放置列表使用实际设备与已解析普通照明回路，不提供实体开关、中控屏或无线副控。旧开关位置保留在编辑器中供移除，但不再作为 3D 标记显示；请从照明目标列表放置对应灯具。

灯具可选择吸顶灯、吊灯、射灯、灯带或面板灯轻量模型；灯体在关闭时仍可见，只有确认开启后才产生照明，且不绘制地面光晕。已读取或写入回读确认的亮度改变光照强度；光照使用受控强度避免高亮表面过曝。支持色温的灯具会读取 MIoT `color-temperature`，让灯体和照明颜色按实际开尔文值变化，并在快捷面板提供冷暖控制；读取失败时保留中性偏暖的默认显示，不猜测设备色温。直接有线回路只代表明确的电源控制，不自动等同于灯：例如排风扇保留为风扇设备和对应图标，不生成灯光效果。空调开启显示离地的静态气流环，目标温度显示在标记并改变环的范围（仅示意，不代表实测温度或覆盖范围）。未知、离线及未确认写入不会开启效果。聚焦单个房间或区域时，其他空间的结构、家具和灯体显示为中性线框，并隐藏其中的标记与活动效果；聚焦空间及其边界墙保持完整实体显示。

3D 墙与转角统一采用布局 defaults.wallThickness（默认 0.12 米），原始图片识别厚度仍用于图纸编辑。查看时从布局重建模型，使已有布局立即得到统一墙厚；下载的历史 GLB 需重新保存后更新。


设备放置步骤中选择已放置目标，或点击位置列表的“外观”，可编辑方向和长度。灯光支持点、灯带、面三种示意：灯带最多 32 段连续连接，每段独立长度与方向，面光源可编辑长宽。图纸预览与 3D 共用校准米制尺寸。外观只影响显示，不创建新的设备能力。方向/尺寸输入允许中间输入状态，按 Enter 或失焦应用；非法值恢复原值。移动已放置设备保留外观配置。

设备编辑器固定为两层：第一层只负责搜索和选择当前家庭的设备或照明目标；第二层只显示当前选择的属性。已放置对象的 X/Y/Z、所属空间、方向、视觉形态、尺寸和移除入口都在第二层，点击图纸标记也会选择该对象。未放置目标的第二层仅设置初始高度并提示到图纸落点。


### 全屏触控

3D 视图的「全屏控制」保留当前相机、设备状态与快捷控制，隐藏页面导航、页头、页脚及助手。支持浏览器原生全屏；浏览器不提供或拒绝全屏时使用应用视口全屏（浏览器地址栏可能保留）。退出按钮与 Escape 均恢复页面及键盘焦点。全屏中可直接点设备标记，或打开按空间分组的设备列表；横屏快捷控制浮在右侧，竖屏使用可滚动底部面板。触控目标至少 48px，支持单指旋转、双指平移及捏合缩放。高级设备详情先退出全屏，演示模式仍显示只读提示。
