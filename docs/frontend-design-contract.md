# 前端页面风格与交互约束

版本：1.0 · 2026-09-23 · 适用：米家 Web 控制台、内嵌 AI 助手及后续相关前端。

本文是后续开发 Agent 的执行约束，不是本轮页面改造任务。**必须**表示验收要求，**建议**表示默认选择，偏离建议时应说明原因。本文仅增加文档，不代表所述增强能力已经实现。

## 1. 执行与维护

1. 前端开发前必须阅读本文、仓库 `AGENTS.md` 和目标模块；涉及设备时同时阅读 [设备管理设计](device-management-design.md)。
2. 先复用组件、领域数据和共享样式，再扩展；不得因新页面引入第二套主题、字体体系或组件库。
3. 安全、访问权限、数据契约和设备领域规则优先于视觉约定。控件建议不授予新的设备控制能力。
4. 新页面与新增组件必须遵守本文。修改旧页面时使本次涉及的组件收敛，不借此重写无关页面；存量差异需在交付中记录。
5. 改变公共规范时，先在同一变更中更新本文，说明理由、影响页面与验证方式；不得只在单个页面中静默覆盖。
6. 本文是唯一完整规范，存放在实际拥有前端的 web-console 仓库；mijia-agent 仓库通过 `AGENTS.md` 引用。若仓库未检出，应先取得本文，不另造相互冲突的副本。

## 2. 当前风格与本版决策

基线来自 2026-09-23 本地工作区源码，包含当时已有的未提交改动；未对线上站点或真实设备做验证。

| 依据 | 已有风格或语义 | 后续约束 |
| --- | --- | --- |
| [`globals.css`](../app/globals.css)、[`responsive.css`](../app/responsive.css) | 浅灰工作区、白卡片、橙色重点、细边框、轻阴影；桌面侧栏 | 保持明亮、紧凑、易扫描的控制台风格 |
| [`typography.css`](../app/typography.css)、[`layout.tsx`](../app/layout.tsx) | 共享字号文件最后加载，统一覆盖部分历史局部字号 | 新组件使用语义字号，不能照抄旧 CSS 中的 7–10px 字号 |
| [`device-management.css`](../app/device-management.css)、[设备管理设计](device-management-design.md) | 房间筛选、硬件/实际照明视图、卡片与拓扑 | 房间优先，保留领域模型，不把端点当独立物理设备 |
| [`environment-dashboard.css`](../app/environment-dashboard.css) | 数值卡、趋势图及独立 `--viz-*` 图表色 | 图表复用该色板；局部深色图表不等于全站已有深色主题 |
| [`ai-assistant.css`](../app/ai-assistant.css) | 右侧浮动助手、消息气泡、结构化结果卡 | 助手沿用主站视觉，结果卡复用相同状态语义 |

本版新增的间距档位、可访问配色、控件映射、组合筛选与验收要求是**后续实现标准**，不是已存在的 token 或组件清单。现有样式仍有零散数值、浅色小字与覆盖规则；不得把这些差异视作继续扩散的依据。

## 3. 配色

### 3.1 已有基础色

| 现有变量或颜色 | 值 | 使用边界 |
| --- | --- | --- |
| `--bg` | `#fafbfc` | 页面工作区背景 |
| 白色表面 | `#ffffff` | 卡片、表单、弹层 |
| `--ink` | `#17202b` | 主文字、标题、关键数值 |
| `--line` | `#e9edf2` | 装饰性分隔线、卡片边框 |
| `--orange` | `#ff6b2c` | 品牌、重点图形；不能默认保证与白字的对比度 |
| 浅橙背景 | `#fff2ec` / `#fff0e9` | 当前导航、选中背景、图标底色 |
| `--muted` | `#89939f` | 现有弱化色；不得直接用于新增的小字号必要信息 |

### 3.2 新增和改动组件的可读性配色

下列为规范 token，在共享样式中定义并复用，不在每个组件重复硬编码。

| 建议 token | 色值 | 用途 |
| --- | --- | --- |
| `--text-secondary` | `#596574` | 次级说明、更新时间、单位 |
| `--accent-text` | `#596574` | 浅底上的链接、选中标签文字；橙色图形使用 mi 标志橙 |
| `--action-primary` | `#ff6b2c` | 与 mi 标志统一的主要按钮底色；主要按钮文字沿用原有白色 |
| `--status-success` / `--status-success-bg` | `#18794e` / `#eaf8f0` | 已确认成功、在线 |
| `--status-warning` / `--status-warning-bg` | `#855800` / `#fff7df` | 过期数据、待确认、部分完成 |
| `--status-error` / `--status-error-bg` | `#b42318` / `#fff0ee` | 失败、危险动作 |
| `--status-info` / `--status-info-bg` | `#245ea8` / `#edf5fe` | 提示、处理中 |
| `--status-neutral` / `--status-neutral-bg` | `#596574` / `#f1f3f6` | 未知、离线、只读的文字与底色 |
| `--control-border` | `#7b8794` | 需要通过边界识别的输入框、未选开关 |
| `--focus-ring` | `#596574` | 可见焦点环，建议 2px、偏移 2px |

必须检查最终前景与实际背景：普通文字至少 4.5:1，大字至少 3:1；必要控件边界与状态图形至少 3:1。不能用加粗、阴影或“品牌色”豁免普通小字的对比度。浅橙背景配深色文字是默认选中方案；主要按钮统一使用 mi 标志橙 `#ff6b2c`，并沿用原有白色按钮文字。

状态必须同时带文字或图标说明，不能只靠红绿。橙色表示交互重点，绿色表示已确认结果，二者不得混淆。图表系列色表示数据系列，不隐含健康或安全评价；没有已确认阈值时不得自行标注“安全”“危险”。

## 4. 字体与排版

字体沿用 `Inter, "SF Pro Display", "PingFang SC", "Microsoft YaHei", Arial, sans-serif`；这些是字体候选，并不代表项目已下载对应字体。禁止为单个页面新增远程字体依赖。

| 用途 | 默认字号 | 字重 / 行高 |
| --- | --- | --- |
| 页面主标题 `--font-page-title` | `clamp(28px, 2.2vw, 34px)` | 700 / 1.2 |
| 分区标题 `--font-section-title` | 16px | 600–700 / 1.4 |
| 卡片名称、主要标签 `--font-label` | 14px | 600 / 1.5 |
| 正文、表单值 `--font-body` | 13px | 400 / 1.5；长说明或对话可用 1.7 |
| 紧凑按钮 `--font-control` | 12px | 600 / 1.5 |
| 辅助元信息 `--font-meta` | 11px | 400 / 1.45 |
| 环境主读数 | 26px | 700 / 1.2，数字使用等宽数字特性 |

- 新增必要操作说明、错误原因不得使用 11px 元信息层级，至少正文档位。不得新增小于 11px 的可读文字。
- 手机可编辑输入框建议至少 16px，避免聚焦时自动放大；这是共享字号的明确响应式例外。实现时应处理 `typography.css` 最后加载及已有 `!important` 的实际级联，不能只写一个被覆盖的局部规则。
- 新组件不得继续扩张全局 `!important` 覆盖表。共享字号调整须检查所有消费页面，新增例外须有语义和验证理由。
- 长设备名允许两行或省略并提供可聚焦/可点击的完整名称入口；不能只用鼠标悬停提示。状态、数值和单位不得被截断。
- 页面只设一个主标题，分区标题依次嵌套；不能只为字号效果选择标题标签。

## 5. 间距、形状与布局

新增布局统一采用 **4、8、12、16、24、32、48px** 间距档位。现有 13/14/15/18/22px 等不是必须立即迁移的缺陷；扩展组件时选最近的语义档位，避免继续增加随意数值。

| 位置 | 新增布局默认值 |
| --- | --- |
| 图标与文字、标签与输入框 | 8px |
| 卡片内相关信息、筛选控件间距 | 12px |
| 卡片内边距、卡片网格间距 | 16px |
| 房间分组间距 | 24px |
| 主要页面分区间距 | 32px |
| 手机页面左右留白 | 16px；极窄屏可沿用现有 13px |
| 桌面工作区 | 复用现有容器 `36px clamp(22px, 2.5vw, 44px) 72px` |

形状：按钮/输入框圆角 10px，小卡片 14px，大面板 18px，助手面板可沿用 22px，状态徽标与筛选 chip 使用 999px。常规卡片 1px 细边框；默认不叠加重阴影。可点击卡片 hover 建议 `0 8px 24px rgb(29 40 51 / 7%)`，位移最多 2px；只读卡片不伪装可点击。

按钮与输入框建议高 44px；紧凑桌面表格可用 36px。触控目标必须至少 44×44px，可扩展热区，但不得与相邻热区重叠。图标一般 16/20px，设备图标 24px 配 40px 底座。新增同类图标使用统一图标来源；状态不可仅依赖 emoji 的系统外观。

### 响应式约定

| 范围 | 行为 |
| --- | --- |
| 大于 1320px | 复用最大宽度 1920px 的现有外壳；侧栏、主区、可选信息栏 |
| 761–1320px | 主区优先，次要右栏收起；其中 980px 断点沿用现有窄侧栏 |
| 不大于 760px | 单列主体与可关闭导航抽屉，主要操作入口保留 |
| 不大于 560px | 设备列表默认单列；筛选区换行或进入筛选面板 |

设备网格建议最小卡宽 240px，自适应列数；不能以固定三列挤压名称。复用目标模块已有 430/440/600px 等局部断点时说明用途，不为每个新组件建立独立断点体系。

320px 宽不得出现页面级横向溢出；房间 chip 条可局部横向滚动，必须有溢出提示与键盘可达项。表格可在明确的局部区域滚动，移动端优先转为标签—值列表。底部操作与助手输入框应考虑 `safe-area-inset-bottom`、`100dvh` 和软键盘，不遮住最后一项内容。

## 6. 页面信息层级

默认顺序：**页面标题与家庭选择 → 摘要 → 房间筛选 → 视图切换与其他筛选 → 分组内容 → 次要说明**。

- 一个局部任务区只有一个主要按钮；刷新、返回、详情用次要样式。危险动作单独标注，不以品牌主按钮美化。
- 概览优先展示环境、当前开启设备、常用场景和需关注状态；详细配置进入设备/场景页面，不把所有参数铺满首页。
- 常用/收藏是额外入口，不能替代完整的按房间浏览；仅在产品实际支持保存时提供收藏控件。
- 不为纯展示项增加按钮外观。卡片名称区域打开详情，控制使用独立明确按钮，不能点击整张卡就意外执行场景。
- 默认先卡片摘要再详情；设备硬件卡的真实通道及目标依照领域规范直接显示，不因“简洁”隐藏关键关系。

## 7. 设备必须按房间组织，支持组合筛选

### 7.1 分组和身份

- 第一层始终是当前家庭；“全屋”下按房间分段，标题含房间名和当前结果数量。
- 房间排序优先使用服务端明确顺序，否则稳定排序；缺少房间放入末尾“未分配房间”。未知设备类型放入“其他/未知”，不能丢弃。
- 房间列表同时覆盖物理硬件房间和照明目标房间。硬件用自身房间；实际照明用领域模型的 `targetRoom`，不能按名称重新推断。
- 每个物理设备一张硬件卡，派生端点嵌入其服务列表；每个已解析照明目标一张目标卡。不能仅凭显示名称去重或跨家庭合并。
- 分组前完成当前家庭的关系解析，筛选只改变展示，不能截断拓扑匹配输入。

### 7.2 控件与筛选语义

| 维度 | 默认控件 | 约定 |
| --- | --- | --- |
| 家庭 | 单选下拉，展示家庭名称 | 常驻标题区；切换后清空旧家庭数据、选中对象和未提交控制上下文 |
| 房间 | “全屋”加房间 chip；很多房间时可搜索下拉 | 默认单选；手机保持可达 |
| 视图 | 分段控件“开关与硬件 / 实际照明” | 位于房间之下，切换保留家庭与房间 |
| 设备类型 | 多选 chip 或带复选框的筛选菜单 | 仅显示当前视图支持的真实类别 |
| 连接状态 | 多选：在线、离线、未知 | 与电源状态分开建模 |
| 电源状态 | 多选：开启、关闭、未知 | 无可读电源属性不等于关闭 |
| 名称搜索 | 带清除按钮的搜索框 | 搜索可见名称、房间名、类型标签；不要求用户输入 DID |
| 排序 | 单选下拉，默认稳定顺序 | 可提供名称/状态排序，不能在后台刷新时任意跳动 |

不同维度取 AND，同维度多选取 OR；空选表示该维度不限。示例：“客厅 AND（灯或开关）AND 在线 AND 开启”。搜索再与这些条件取 AND。搜索仅作用于当前家庭，不能扩大权限。

建议 6 个以内房间直接展开，更多时提供搜索/溢出入口；这是布局建议，不是隐藏第 7 个房间的规则。手机高级筛选可集中到抽屉，入口显示已启用条件数量，顶部仍显示已选条件及逐项清除入口。

必须提供结果计数和“清除筛选”。计数写明范围，例如“当前筛选 8 个 / 本视图 24 个”，不能混用物理设备、通道、照明目标数量。清除筛选保留当前家庭与视图，重置房间为全屋、其他条件为不限。切换家庭重置房间及其他家庭相关筛选；切换视图保留仍有效的筛选，若某条件不适用，清除并提示。

无匹配结果显示“没有符合条件的设备”及清除筛选；整个家庭确实为空显示“当前家庭暂无设备”。后台刷新保留有效筛选和滚动位置；迟到的旧家庭请求结果不得覆盖新家庭页面。

默认只在当前会话保存筛选。不把家庭标识、设备标识或敏感搜索词放进可分享 URL，也不因方便而持久化真实家庭数据。

## 8. 数据类型 → 推荐控件

选择顺序：**先检查是否可读/可写与当前权限，再检查类型、枚举和范围，最后选择控件**。缺少可信能力描述时只能展示未知/只读；不得按设备名称臆造滑块或控制开关。

| 数据或任务 | 推荐形式 | 必须满足 |
| --- | --- | --- |
| 可读写布尔，如电源 | Switch + 明确状态文字 | 已知当前值且允许写；未知时不显示为 off，改为未知及明确命令入口（仅在契约允许时） |
| 只读布尔，如在线 | 状态徽标/图标与文字 | 无可点击开关外观 |
| 少量互斥枚举（2–4） | Radio / 分段单选 | 使用真实标签；标签过长改下拉 |
| 更多枚举 | Select，可搜索选项 | 选项值取自规格；未知枚举显示不支持，不随意映射 |
| 连续有界数值，如亮度 | Slider + 数值输入/读数 + 单位 | 遵守 min/max/step；拖动预览，明确提交时写入，不逐像素发设备命令 |
| 精确整数/小数，如阈值 | 数值输入，可带步进按钮 | 校验范围、步长、精度；显示字段级错误 |
| 仅写属性 | 值输入 + “设置”按钮 | 不虚构当前值，不用假状态开关 |
| 无参数即时动作 | 动词按钮，如“执行场景” | 打开详情与执行分离；沿用服务端权限和安全门禁 |
| 带参数动作 | 小表单 + 明确执行按钮 | 参数完整校验；不把 Action 参数当额外属性写入 |
| 名称/备注 | Input / Textarea | 可见 label、长度限制与错误说明，placeholder 不替代标签 |
| 多设备/多房间选择 | 搜索 + 按房间分组 Checkbox | 显示已选数量；“全选”必须说明仅当前筛选结果 |
| 批量配置 | 选择列表 + 汇总/预览 + 保存 | 展示混合值；验证每个对象能力，逐项报告结果 |
| 日期、时间、每周重复 | Date/Time 输入 + 星期多选 | 显示时区、重复规则摘要，不能自动建立提醒任务 |
| 温湿度等当前读数 | 数值卡 + 单位 + 来源/房间/采集时间 | 无值用“暂无数据”，合法 0 不能变为空值 |
| 历史时间序列 | 折线图 + 时间范围 + 可访问数据表 | 缺测断线、单位清晰；没有历史数据不得伪造趋势 |
| 房间设备集合 | 房间分区 + Tile 卡片网格 | 名称、类型、状态、主要入口；支持第 7 节筛选 |
| 场景 | 摘要卡 + 动作列表 + 独立执行入口 | 名称、动作数、可执行状态；AI 远程写门禁未开放则不提供可用执行入口 |
| 自动化规则 | IF/THEN 分区与可读摘要 | 未知条件/厂商私有节点只读保留；不得生成当前不存在的删除功能 |
| 拓扑/控制关系 | 目标列表 + 关系图 + 文字详情 | 有线实线、无线虚线、未知明确标记；图之外保留可操作列表 |
| AI 工具结果 | 消息内结构化结果卡 | 按契约渲染，不把测量值或设备状态回填到模型消息 |

Switch 表示可保持的状态，Checkbox 表示选择项，Button 表示一次动作；三者不能因视觉方便互换。筛选选择不触发物理设备动作。

## 9. 状态、反馈与安全语义

| 情况 | 必须展示 | 交互约束 |
| --- | --- | --- |
| 首次加载 | 与目标布局接近的骨架或加载说明 | 不闪现“0 台设备/全部关闭” |
| 后台刷新 | 保留已有内容 + 更新中提示 | 显示旧采集时间，不冒充刚更新 |
| 部分读取失败 | 可用结果 + “部分数据未获取” | 不清空成功结果，不显示完整成功 |
| 离线 | “离线”，必要时展示带时间的最近已知值 | 不等于关闭；不可用操作解释原因 |
| 状态未知 | “未知/暂不可用” | 不默认为 false、0、无绑定 |
| 数据过期 | “上次更新…”或“数据可能已过期” | 优先消费服务端 freshness；不得自造业务时效阈值 |
| 写入处理中 | 目标控件禁用 + “执行中” | 防重复提交，不先宣告物理状态改变 |
| 已确认完成 | 回读状态或契约确认的结果 | 不能仅凭模型回复报告成功 |
| 明确失败 | 目标附近错误 + 可行的下一步 | 保留原值和输入；不自动重试写入 |
| 写入超时/结果不明 | “执行结果待确认，请刷新状态核实” | 不显示已失败或已成功；不提供一键重发，先核查结果 |
| 权限不足/只读 | 可读内容 + 简短原因 | 隐藏或禁用不可用操作，前端不能绕过服务端检查 |
| 预览 | 持续显示“演示数据/只读预览” | 不调用模型、不控制设备 |

字段错误紧邻字段；整页错误用可恢复的页面状态；toast 仅补充短反馈，不能成为失败或不确定结果的唯一记录。批量动作分别报告成功、失败、待确认，不用一个绿色提示覆盖部分失败。

AI 消息必须区分“正在生成回复”“正在读取设备”“执行结果待确认”。停止生成不代表已撤销物理动作。助手环境卡显示来源与时间，设备卡仍按房间分组；不要复制一套不同的卡片状态规则。当前远程执行未开放、提醒与学习习惯仍属未来能力，不得通过新 UI 暗示已支持。

## 10. 可访问性、动效与弹层

- 所有控件使用真实语义与可访问名称；图标按钮具有名称，开关具有状态，筛选 chip 具有选中语义。仅用 `div onClick` 不合格。
- 键盘可完成筛选、进入详情、编辑和关闭弹层；焦点始终可见。模态框移入焦点、限制焦点在框内、关闭后还给触发按钮；非模态助手不得无故困住页面焦点。
- 弹层标题和关闭入口始终可达；避免弹层套弹层，长编辑优先独立页面。未保存改动按实际风险提示，不能让每次查看都出现确认框。
- 加载与结果用适度的 live region 宣告，不能在每次传感器刷新时打断读屏。
- 不依赖 hover、颜色、手势或图形才能完成任务；图表和拓扑提供文字/表格等价信息。
- 常规过渡 150–200ms，限制在颜色、透明度或轻微位移；遵守 `prefers-reduced-motion`。不使用持续闪烁提示设备在线。
- 新增层级先检查现有侧栏、弹层与助手的层叠关系；不随意增加超大 z-index，弹层不得被助手悬浮按钮覆盖。
